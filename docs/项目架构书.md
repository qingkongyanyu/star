# 星枢 StarPivot · 项目架构书

> 版本：v3.2 商业版（2026-10-19）｜ 描述**当前实际落地**的架构（含意图驱动分析计划、多任务取数、图表选择引擎、洞察分析、图文表报告、数据源接入、任务工作台、ACL、知识库、商业版认证与异步执行）。

## 一、系统定位

**一句话**：输入一句分析需求，12 个 Agent 按 DAG 编排协作，对**真实接入的数据源**完成意图规划→探查→取数→质检→可视化→洞察→报告，产出**基于真实数据的图文表并茂分析报告**与资产。

v3 的关键变化：天枢先产出结构化 `AnalysisPlan`（意图 × 指标 × 维度 × 时间粒度 × 过滤 × TopN × 图表偏好），再拆成最多 4 个子任务并行取数；报告结构与图表类型随意图变化，不再「一套模板走天下」。

适用场景：业务数据分析自动化、指标口径统一、分析过程可审计、多角色协同。

## 三、数据库设计（双库隔离 + 业务源分离）

| 库 | 位置 | 用途 |
|---|---|---|
| `task_repo` | Docker MySQL | 任务/DAG/节点/审计/用户/ACL/**数据源配置**/**指标知识库**/记忆 |
| `artifact_repo` | Docker MySQL | 资产索引（文件在 MinIO） |
| **业务数据源** | 独立接入 | 被分析的订单/销售等真实数据（通过「数据源接入」配置，与平台库隔离） |

**关键表（task_repo）**：task（含 `data_source_id`）、dag_node、dag_edge、audit_log、user、admin_acl、agent_config、memory_entry、kb_indicator、data_source（数据源接入，config JSON）。

> 说明：早期版本曾引入 PostgreSQL（LangGraph 检查点）与 Qdrant（向量记忆），已在重构中收敛移除——编排为自研确定性 DAG，记忆检索走 MySQL 关键词匹配。

## 四、12-Agent 编排（DAG）

**确定性模板拓扑**（非 LLM 拆解，保证可测可审计；差异化体现在 AnalysisPlan 子任务，而非随意改拓扑）：

```
metadata_profiling → metric_definition → sql_extract → quality_check → visualization → insight_analysis → report_writing → review
                                                                  ↘ feature_engineer（仅 DQ 警告/阻断时）
                                                                  ↘ trace（溯源意图按需追加）
```

| Agent | 名称 | 能力 | 产出 |
|---|---|---|---|
| Planner 调度 | 天枢_调度 | 规则 NLU + 可选 LLM 槽位补充；产出 AnalysisPlan 与 DAG | plan + DAG |
| 指标定义 | 素问_指标定义 | 指标目录（SUM/AVG/COUNT DISTINCT/客单价/毛利率）+ 知识库口径校验 | metric_specs |
| 数据探查 | 观澜_数据探查 | 读真实表结构/字段/行数（按需求关键词选表） | profile |
| SQL抽取 | 灵枢_SQL抽取 | 按计划逐子任务生成 SQL / 内存聚合 → **真实取数** → `datasets[]`；逐表过 **ACL**；单任务失败隔离 | sql + datasets |
| 数据质检 | 明鉴_数据质检 | 逐数据集评分 + 跨集一致性（合计/断月/占比）校验 | dq_report |
| 特征工程 | 炼金_特征工程 | 清洗 + **visual_hints**（基数/时间连续性/零方差/推荐与禁用图型） | feature_set |
| 可视化 | 丹青_可视化 | 图表选择引擎：按意图 × 数据结构 × hints × 用户偏好选型并生成 ECharts option；同任务图型去重 | charts[] |
| 洞察分析 | 天机_洞察分析 | 确定性算子（趋势/对比/构成/分布/相关/异常/归因/双指标交叉）产出带证据的发现，可选 LLM 写解读 | insight/findings |
| 报告编撰 | 文澜_报告编撰 | **确定性**拼装动态章节 Markdown（图号/表号/引用/口径/质量/SQL 附录）；导出内嵌 PNG | report |
| 终审 | 洛璃_终审 | 逐数据集数字复算 + 图表引用/章节/表格结构校验 | review |
| 记忆管理 | 忆安_记忆管理 | 任务后复盘，沉淀经验到记忆库 | retrospective/memory |
| 溯源 | 闻道_溯源 | 血缘回放（chart → dataset → metric_spec）、问责（按需触发） | trace |

## 五、数据源接入（新增）

- 6 类：`mysql / postgres / olap / file(CSV) / stream(Kafka) / api`
- 数据源配置存 `data_source` 表（config JSON），连接器 `app/infra/datasource.py`
- 管理接口 `/api/v1/data-sources/*`（管理员）；任务下发用脱敏 `/api/v1/data-sources/options`（所有登录用户）
- **真实取数引擎**：MySQL/Postgres 已走通（生成 SQL → 执行 → 数据集）；OLAP 用 SQLAlchemy URL 可复用；CSV 解析类型推断；API 推断 JSON 字段；Kafka 探测 topic
- 演示数据：本机 MySQL80（3307）`analysis_biz`，账号 `midplat_biz`

## 六、真实数据分析链路（关键）

```
任务(带 data_source_id)
  → Planner 真实读源结构 + 指标目录 → AnalysisPlan（intent/metrics/dims/time/filters/topN/tasks）
  → DataProfiler 真实读表结构（profile 含 table/columns/row_count）
  → MetricDefinition 按真实列名定义多个指标口径（知识库口径需通过列存在性/聚合语义校验）
  → SQLAgent 按子任务生成只读聚合 SQL / 内存聚合 → 执行取数 → datasets[]{columns,rows,row_count}
     （逐表过 ACL；单个子任务失败只标记该数据集，其余继续）
  → DataQuality 逐数据集评分 + 跨集一致性校验
  → FeatureEngineer 清洗并输出 visual_hints（数据适合/不适合什么图）
  → VisualAgent 图表选择引擎 → charts[]{type/option/data/rationale/insight}
  → InsightAnalyst 确定性算子产出 findings[]{evidence/chart_refs/severity}
  → ReportScribe 动态章节 + 图号/表号 + 图文表并茂报告（导出 .md 内嵌 PNG）
  → AnalystReview 复核报告数字、图表引用与口径
```

**数据透传链**（每一环都透传 plan / datasets / metric_spec / dq / charts，保证报告数字与图引用真实）。

## 七、资产与血缘

- 每个节点产出经 `publish_artifact` 写入 MinIO（JSON）+ artifact_repo 索引
- 资产类型：metric_spec/profile/sql/dataset/dq_report/feature_set/chart/insight/report/review/retrospective/trace
- DAG 节点记录 `output_asset_id`，支持血缘回放与溯源
- **下载即干净文件**：报告→.md、SQL→.sql、结构化→排版 JSON（前端 Blob 下载）

## 八、记忆体系

- MemoryKeeper 任务成功复盘，写 memory_entry（MySQL 关键词匹配检索）
- 12 套私有 + 集体记忆；按任务可查（`/tasks/{id}/memory`）
- Agent 知识库页可看每个 Agent 的职责与系统提示词

## 九、权限与安全

- **认证**：JWT（HS256，argon2 密码哈希）
- **三档角色**：admin / analyst / readonly（菜单权限不同，任务/资产/数据源共享）
- **表级 ACL（已强制）**：admin_acl 规则「角色或用户 × 表(支持 *) × 操作」，SQLAgent 取数前拦截；拒绝优先，无规则默认允许（只读）
- 数据源列表对分析师**脱敏**（`/options` 不含密码）
- 审计日志（audit_log，SHA-256 防篡改）

## 十、前端架构

- React 19 + TypeScript（strict）+ Vite + antd6（浅色秋季主题）+ ECharts + zustand + axios + react-markdown
- 页面：登录（秋季山湖实景 + 独立暖色主题）、协同群聊（12 Agent 以各自身份发言）、任务看板、**任务工作台**（DAG/多图型可视化大屏 + 关键洞察/资产/记忆 四 Tab）、数据大屏（平台 KPI）、资产仓库、数据源接入、Agent 知识库、系统管理、记忆检索

## 十一、部署架构

- 中间件：Docker Compose（MySQL/Redis/Kafka/MinIO，精简四件套）
- 后端：uvicorn（本机手动重启，`--reload` 不可靠）

## 十二、已知限制与演进

- OLAP/实时流/API 支持登记+测试+结构读取；真实取数引擎已覆盖全部 6 类（MySQL/Postgres/OLAP/CSV/API/Kafka）
- ACL 默认"无规则允许"，生产可收紧为默认拒绝；insert/update/delete 规则暂无写入路径
- 知识库检索为 MySQL LIKE 评分（RAG-lite），未接向量
- 报告应用内用 ECharts 交互渲染；导出 .md 时自动把 `chart://` 替换为内嵌 PNG（matplotlib/Pillow）
- 多维度交叉（区域×渠道×月份）当前用多个单维子任务表达，未合并成一张多系列图；地图类图表按需求未做
- 图表选择以规则为主，LLM 只补槽位/文案；用户可在需求中显式点名图表类型

## 十三、商业版认证与异步执行（v3.2）

**认证与账号**
- 无内置账号；首个管理员由 `BOOTSTRAP_ADMIN_*` 或 `python -m app.cli create-admin` 创建。
- 口令强度策略（≥10 位、三类字符、弱口令黑名单）；argon2 只存哈希。
- 登录需账号 + 口令 + 一次性图形验证码；失败按账号与来源 IP 双维度计数，超限 429。
- `ENV=prod`：强 JWT 校验、关闭 API 文档端点、安全响应头、CORS 白名单。

**异步执行**
- API / 调度 / Agent 全 async；同步 SQLAlchemy 与 MinIO 调用经 `to_thread`。
- 验证码与登录限流使用 `redis.asyncio`，Redis 故障自动降级内存。
- 节点上游资产并发拉取（独立会话 + 并发上限）；就绪探针 `/readyz` 并发探测依赖。
