# 云部署上手指南（星枢 StarPivot · 商业版）

> 目标：从「本机 uvicorn/vite」平滑上云。云能力由环境变量开启，不配置时保持本地默认
> （进程内广播 / 内存验证码 / 本地资产降级），因此本地仍可裸机测试。
> 商业版部署必须显式配置强密钥与初始管理员，**不存在默认账号**。

## 0. 本地可测性（红线，未破坏）

| 能力 | 本地（默认） | 云（配置后） |
|---|---|---|
| 事件广播 | `EVENT_BUS_REDIS=false` → 进程内 `EventHub` | `=true` + `REDIS_URL` → Redis Pub/Sub 跨副本 |
| 验证码 | Redis 不可达 → 进程内存 | 异步 Redis 共享一次性校验 |
| 登录限流 | Redis 不可达 → 进程内存 | Redis 多副本共享失败计数 |
| LLM | MockLLM / 真 key | 单次超时 + 客户端重试 |
| 记忆检索 | `memory_entry`（MySQL 关键词匹配） | 同左（无外部向量库） |
| 运行方式 | `python -m uvicorn` + `vite` | 见下容器化 |

本地回归入口：`cd backend && ../.venv/Scripts/python.exe -m pytest`（应全绿）。

## 1. 必读：生产前置条件

复制并编辑环境模板：

```bash
cp .env.cloud.example .env
```

以下变量**缺失时 compose 直接报错**，避免带着默认口令上线：

| 变量 | 要求 |
|---|---|
| `JWT_SECRET` | ≥32 位随机串；`ENV=prod` 时启动强校验 |
| `LLM_API_KEY` / `LLM_BASE_URL` | 真实可用模型（可选，但建议配置） |
| `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` | 首个管理员；口令 ≥10 位且至少三类字符 |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_APP_PASSWORD` | 独立强口令，禁止沿用本地 `root`/`secret` |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 独立强口令，禁止沿用 `minioadmin` |
| `CORS_ORIGINS` | 前端真实域名（逗号分隔） |

首次启动后建议从部署环境移除 `BOOTSTRAP_ADMIN_PASSWORD`（已有管理员时该配置不会再生效）。
如需重置口令：

```bash
docker compose -f compose.cloud.yml exec backend python -m app.cli reset-password --username admin
```

## 2. 应用容器化（后端 + 前端）

```bash
# 校验 compose 变量是否齐全
docker compose -f compose.cloud.yml config -q
# 构建并启动
docker compose -f compose.cloud.yml up -d --build
# 访问
open http://localhost:8080      # nginx → /api 与 /ws 反代到 backend:8070
# 探针
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
```

> - 后端容器启动时先执行 `alembic upgrade head`（幂等），再起 uvicorn；
> - 容器 backend 映射宿主 8070、frontend 映射 8080；与裸机 uvicorn 同时运行会占用同一端口，二选一；
> - `ENV=prod` 时 `/docs`、`/redoc`、`/openapi.json` 按设计关闭；
> - `/readyz` 返回 `ready` / `degraded`（Redis 或 MinIO 降级）/ `not_ready`（DB 不可用，HTTP 503）。

## 3. 镜像说明

- `backend/Dockerfile`：python:3.13-slim，`pip install .`（构建上下文=项目根），HEALTHCHECK 打 `/healthz`。
- `frontend/Dockerfile`：node:20-alpine 构建 → nginx:alpine；`frontend/nginx.conf` 反代 `/api/`、`/ws/`（WebSocket upgrade）+ SPA 回退。
- `compose.cloud.yml`：后端 8070、前端 8080:80；依赖中间件服务名（mysql/redis/minio/…），数据库/MinIO/管理员等敏感配置全部来自 `.env`。

## 4. 云替换建议（把「本机中间件」换成云托管）

- 业务库/资产库 → 云 RDS MySQL（双库隔离，改 `DATABASE_URL`/`ARTIFACT_DATABASE_URL`）。
- 制品 → 云 OSS/S3 兼容，改 `MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY`（代码已按 S3 兼容预签名实现）。
- 事件总线/验证码/登录限流 → 云 Redis，`EVENT_BUS_REDIS=true` + `REDIS_URL`；多副本横向扩容即共享。
- 模型 → 合规大模型 OpenAI 兼容 `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL`。
- 调度：多副本时 SchedulerWorker 基于 MySQL 租约/CAS 天然多 worker 安全，任意副本都可接管。
- 安全：`ENV=prod` + 强 `JWT_SECRET`；CORS 指向真实域名；密钥交给 Secret 管理服务。
- 入口：在负载均衡上把 `/healthz` 与 `/readyz` 配为探针；`/readyz` 失败时摘流。
- 备份：RDS 自动备份 + 对象存储版本化；定期做恢复演练。

## 5. 每次发布的回归清单

1. `cd backend && <py> -m pytest`（全绿）
2. `cd <项目根> && <py> -m ruff check backend/app backend/tests` 与 `<py> -m mypy backend/app`
3. 前端：`cd frontend && npm test && npm run lint && npm run build`
4. 裸机冒烟：起中间件 + uvicorn + vite → 登录（错误口令 401 / 连续失败 429）→ 下发 mysql/CSV 任务到 SUCCESS
5. 容器：`compose.cloud.yml config -q` 通过后 `up -d --build`，curl `/healthz` 与 `/readyz`
6. 12-Agent E2E：`./.venv/Scripts/python.exe scripts/e2e_agents.py --keep-going`
