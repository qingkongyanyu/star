# 前端权限与安全

> 前端权限是**体验层**约束（隐藏/禁用入口），真正的数据安全在后端（JWT + ACL + 脱敏）。前端不自行决定可访问性。

## 一、角色与可见性

| 模块 | admin | analyst | readonly |
| --- | :---: | :---: | :---: |
| 协同群聊（下发任务） | ✅ | ✅ | ✅ 查看 |
| 任务看板（人工干预） | ✅ | ✅ | 查看，无干预按钮 |
| 资产仓库（下载/溯源） | ✅ | ✅ | ✅ 查看/预览 |
| 可视化大屏 | ✅ | ✅ | ✅ |
| 系统管理 | ✅ | — | — |
| 记忆检索中心 | ✅ | — | — |

```ts
// 页面/组件内按角色做体验层判断（真正权限仍由后端接口校验）
const user = useAuthStore((s) => s.user);
const isAdmin = user?.role === 'admin';
// 例：仅 admin 渲染系统管理入口；后端仍会对越权请求返回 403
```

## 二、路由守卫（见 03-路由与页面）

- `RequireAuth`：无 token → `/login`。
- `RequireRole admin`：`/admin`、`/memory` 模块仅 admin。
- 守卫在路由层执行；组件内仍需 `can()` 二次校验（防深链直达）。

## 三、前端安全约定

1. **不存储敏感数据**：JWT 存 localStorage/sessionStorage；**禁止**存明文密码。
2. **渲染转义**：群聊消息、记忆内容来自 LLM/后端，属不可信数据 → React 默认转义，富文本需过白名单 sanitizer。
3. **注入防护**：资产 ID、任务 ID 一律参数化（`useParams` + 校验格式），不拼接 SQL 语义字符串。
4. **敏感字段**：预览数据集若含手机号/身份证 → 由后端脱敏后下发；前端展示脱敏后数据（后端 `mask_result` 已处理，前端不二次解密）。
5. **下载安全**：文件下载走预签名 URL + 短时有效，不暴露 MinIO 凭据。
6. **审计友好**：前端操作（人工干预/质询/ACL 修改）记录到后端审计（操作人 = 登录用户，前端不伪造身份）。

## 四、登录体验

- 登录页**不展示任何演示账号或默认口令**；仅提示「账号由系统管理员统一分配」。
- 账号 / 密码 / 图形验证码三项必填；验证码一次性、可点击刷新；开启 Caps Lock 时内联提示。
- 「记住账号」只保存用户名到 localStorage，**不保存口令**。
- 失败提示统一 `{ code, message }`，不区分账号不存在与口令错误；429 时展示后端返回的剩余秒数。
- 会话过期：任意接口 401 → 清 token → 跳登录（携带 `redirect`，登录后回跳原页面）。
- 登录成功后按角色进入任务看板；管理员入口由后端 `/auth/me` 权限点驱动。

## 五、二期增强预留

- RBAC 细粒度：前端按权限点动态渲染菜单（`menu` 由后端 `/auth/me` 返回）。
- 字段级脱敏策略：前端展示需按后端字段策略动态打码（二期后端支持后启用）。
- 单点登录（SSO/OIDC）：`/auth/login` 扩展为 OIDC 回调入口。
