# 部署方案

> 部署形态：本地开发 = docker-compose 起中间件 + 本机跑后端/前端；生产 = Docker 镜像 + 单机或轻量集群；
> 可迁移至 K8s（本仓库未内置 K8s 清单，按下方探针/密钥要求编排即可）。

## 一、部署拓扑

```
                          ┌────────────┐
  浏览器 ──HTTPS──► Nginx │  前端静态    │
                          └─────┬──────┘
                          /api   │ /ws
                          ▼      ▼
                 ┌────────────────────┐
                 │  API 网关（JWT/限流） │
                 └───────┬────────────┘
                         ▼
            ┌────────────────────────────┐
            │  后端（12 个能力 Agent）     │
            │  SchedulerWorker / 服务层   │
            └──────┬──────┬──────┬───────┘
                   ▼      ▼      ▼
            Kafka   Redis   MySQL / MinIO
```

## 二、本地开发（最快路径）

```bash
# 1. 基础设施（中间件，精简四件套）
docker compose up -d mysql redis kafka minio

# 2. 后端
cd backend && ../.venv/Scripts/python.exe -m alembic upgrade head
../.venv/Scripts/python.exe -m uvicorn app.main:app --port 8070   # 在 backend 下执行

# 3. 前端
cd frontend && npm install && npm run dev   # 默认 5173，/api 代理到 8070
```

访问：前端 http://localhost:5173 ｜ 后端 Swagger http://localhost:8070/docs

> 也可一键 `bash scripts/start_dev.sh` 起中间件 + 初始化 + 起前后端。

## 三、docker-compose（中间件）

```yaml
services:
  mysql:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: task_repo
    # 本地映射 3307，避开宿主机既有 MySQL
    ports: ["3307:3306"]
    volumes:
      - mysql-data:/var/lib/mysql
      - ./scripts/init_mysql.sh:/docker-entrypoint-initdb.d/init_mysql.sh:ro
    healthcheck: { test: ["CMD-SHELL","mysqladmin ping -h localhost -uroot -p$$MYSQL_ROOT_PASSWORD"], interval: 5s }
  # 本地映射 6381，避开宿主机既有 Redis
  redis: { image: redis:7, ports: ["6381:6379"] }
  kafka:
    image: apache/kafka:3.7.1
    ports: ["9092:9092","9094:9094"]
    environment: { KAFKA_PROCESS_ROLES: broker,controller }
  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    ports: ["9000:9000","9001:9001"]
    environment: { MINIO_ROOT_USER: minioadmin, MINIO_ROOT_PASSWORD: minioadmin }
volumes: { mysql-data: {}, minio-data: {} }
```

**说明**：docker-compose 只起中间件，应用各自 Dockerfile 构建（Dev 用本机进程热更）。MySQL 首启由 `init_mysql.sh` 自动建 `artifact_repo` 库与 `midplat` 账号。

## 四、后端 Dockerfile（多阶段）

```dockerfile
FROM python:3.13-slim AS builder
WORKDIR /app
COPY pyproject.toml ./
RUN pip install .

FROM python:3.13-slim
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.13/site-packages /usr/local/lib/python3.13/site-packages
COPY backend/app ./app
COPY backend/alembic ./alembic
COPY backend/alembic.ini .
EXPOSE 8070
CMD ["sh", "-c", "alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port 8070"]
```

## 五、前端 Dockerfile + nginx

```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm install
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
```

```nginx
server {
  listen 80;
  root /usr/share/nginx/html;
  location / { try_files $uri $uri/ /index.html; }          # SPA 路由回退
  location /api/ { proxy_pass http://backend:8070; }         # 反向代理
  location /ws/  { proxy_pass http://backend:8070;
                   proxy_http_version 1.1;
                   proxy_set_header Upgrade $http_upgrade;
                   proxy_set_header Connection "upgrade"; }
}
```

## 六、生产配置要点（一期）

| 项 | 要求 |
| --- | --- |
| HTTPS | 网关/Ingress 终结 TLS，全链路仅 HTTPS |
| 密钥 | `JWT_SECRET`（≥32 位）、`LLM_API_KEY`、数据库/MinIO 口令走 Secret 注入，禁止进镜像 |
| 初始管理员 | `BOOTSTRAP_ADMIN_*` 或 `python -m app.cli create-admin`；无管理员时生产启动失败 |
| 数据库 | 云 RDS MySQL（task_repo + artifact_repo 双库）；主从/高可用由云服务提供，应用不内置 |
| 日志 | 结构化 JSON 到 stdout，采集进日志平台 |
| 探针 | liveness `GET /healthz`；readiness `GET /readyz`（DB/Redis/MinIO，DB 失败 503） |
| 文档端点 | `ENV=prod` 自动关闭 `/docs`、`/redoc`、`/openapi.json` |
| 备份 | MySQL 每日全量 + binlog；MinIO 桶版本化/异地备份（按云服务能力） |

## 七、扩容模型

- **后端无状态**：可独立扩副本；MySQL 租约/CAS 保证多 worker 安全，任意副本可接管调度。
- **热点瓶颈**：Planner 调度（限流保护）。
- **前端**：静态资源 CDN；WebSocket 多副本需 Redis 发布订阅转发（`EVENT_BUS_REDIS=true`）。

## 八、灰度与回滚

- 版本化发布：镜像 tag = git commit sha；资产版本号保证业务产物可回退（`/assets/{id}/versions`）。
- 回滚：前端回滚 nginx 镜像；后端回滚 Deployment 镜像版本（业务数据不重置，靠资产版本）。
