# 数据模型与迁移

> 双库物理隔离：**TaskRepo**（MySQL 库 `task_repo`）、**ArtifactRepo**（MySQL 库 `artifact_repo` + MinIO）。记忆条目存 `memory_entry` 表（MySQL 关键词匹配，无独立向量库）。
> 本文件为建库唯一依据；任何变更走 Alembic 迁移，禁止手改表。

## 一、ER 总览

```
TaskRepo（MySQL 库名 task_repo）
  task ─┬─ 1:N ─ dag_node
        └─ 1:N ─ audit_log
  dag_node ─┬─ N:M（经 dag_edge）
            └─ 持有 Redis 锁（不在表内）

ArtifactRepo（MySQL 库名 artifact_repo）
  artifact ─ 1:N ─ artifact_version ─┬─ 1:N ─ artifact_dependency（血缘）
```

## 二、TaskRepo DDL

```sql
CREATE DATABASE IF NOT EXISTS task_repo DEFAULT CHARACTER SET utf8mb4;

USE task_repo;

-- 任务主表
CREATE TABLE task (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  task_id       VARCHAR(64)  NOT NULL UNIQUE COMMENT '对外ID',
  req_id        VARCHAR(64)  NOT NULL COMMENT '需求ID（群聊消息）',
  requester     VARCHAR(64)  NOT NULL COMMENT '发起人/角色',
  task_type     VARCHAR(32)  NOT NULL,
  status        VARCHAR(16)  NOT NULL COMMENT 'PENDING/RUNNING/SUCCESS/FAILED/ABORTED',
  priority      TINYINT      NOT NULL DEFAULT 5,
  create_time   DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  update_time   DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  KEY idx_status (status),
  KEY idx_req (req_id)
) ENGINE=InnoDB COMMENT='任务主表';

-- DAG 节点
CREATE TABLE dag_node (
  id               BIGINT AUTO_INCREMENT PRIMARY KEY,
  node_id          VARCHAR(64)  NOT NULL UNIQUE,
  task_id          VARCHAR(64)  NOT NULL,
  agent_type       VARCHAR(32)  NOT NULL COMMENT '能力标签，见 docs/02-后端/06-Agent实现指南.md',
  status           VARCHAR(16)  NOT NULL DEFAULT 'PENDING'
                   COMMENT 'PENDING/READY/CLAIMED/RUNNING/SUCCESS/FAILED/BLOCKED',
  dep_ids          JSON         NULL COMMENT '依赖节点ID列表',
  input_asset_ids  JSON         NULL COMMENT '输入资产 ID@version',
  output_asset_id  VARCHAR(64)  NULL,
  claim_token      VARCHAR(64)  NULL COMMENT 'Redis 锁 token（表内冗余，便于审计）',
  retry_count      INT          NOT NULL DEFAULT 0,
  deadline         DATETIME(3)  NULL,
  create_time      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  update_time      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  KEY idx_task (task_id),
  KEY idx_status (status)
) ENGINE=InnoDB COMMENT='DAG 节点';

-- 依赖边（血缘调度级）
CREATE TABLE dag_edge (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  task_id    VARCHAR(64) NOT NULL,
  from_node  VARCHAR(64) NOT NULL,
  to_node    VARCHAR(64) NOT NULL,
  edge_type  VARCHAR(16) NOT NULL COMMENT 'data_dep/quality_block/review_reject',
  KEY idx_task (task_id)
) ENGINE=InnoDB COMMENT='DAG 依赖边';

-- 审计日志（追加写：应用层禁止 UPDATE/DELETE）
CREATE TABLE audit_log (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  ts          DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  actor       VARCHAR(64) NOT NULL COMMENT '用户或 Agent',
  action      VARCHAR(32) NOT NULL COMMENT 'task.created/artifact.published/dq.blocked/...',
  node_id     VARCHAR(64) NULL,
  asset_id    VARCHAR(64) NULL,
  detail      JSON        NULL,
  checksum    CHAR(64)    NOT NULL COMMENT 'SHA-256(detail)，防篡改',
  KEY idx_ts (ts),
  KEY idx_asset (asset_id)
) ENGINE=InnoDB COMMENT='审计日志，追加写';
```

### 2.5 认证与管理表（Alembic 自设计，文档无 DDL）

`user` / `admin_acl` 按 docs/02-后端/04（登录响应 user 结构）与 07（表级 ACL）设计；
`kb_indicator` 按 /admin/kb 契约（指标知识库条目）设计。均由 Alembic 迁移创建
（0001 建 user/admin_acl，0002 建 kb_indicator）。

```sql
CREATE TABLE user (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(64)  NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL COMMENT 'argon2 哈希',
  role          VARCHAR(16)  NOT NULL DEFAULT 'readonly' COMMENT 'admin/analyst/readonly',
  display_name  VARCHAR(64)  NULL,
  is_active     TINYINT(1)   NOT NULL DEFAULT 1,
  created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)
) ENGINE=InnoDB COMMENT='平台用户';

CREATE TABLE admin_acl (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  role_or_user  VARCHAR(64)  NOT NULL,
  table         VARCHAR(64)  NOT NULL,
  action        VARCHAR(16)  NOT NULL,
  allow         TINYINT(1)   NOT NULL DEFAULT 1
) ENGINE=InnoDB COMMENT='表级 ACL 规则';

CREATE TABLE kb_indicator (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  indicator_key VARCHAR(64)  NOT NULL UNIQUE COMMENT '指标编码',
  metric_name   VARCHAR(128) NOT NULL COMMENT '指标名称',
  category      VARCHAR(32)  NULL,
  formula       TEXT         NULL COMMENT '口径/公式',
  description   TEXT         NULL,
  tags          JSON         NULL,
  owner         VARCHAR(64)  NULL COMMENT '维护人',
  created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)
) ENGINE=InnoDB COMMENT='指标知识库条目';
```

## 三、ArtifactRepo DDL

```sql
CREATE DATABASE IF NOT EXISTS artifact_repo DEFAULT CHARACTER SET utf8mb4;

USE artifact_repo;

-- 资产
CREATE TABLE artifact (
  asset_id        VARCHAR(64) PRIMARY KEY,
  type            VARCHAR(24) NOT NULL
                  COMMENT 'profile/metric_spec/sql/dataset/dq_report/feature_set/chart/report/review/retrospective/trace',
  title           VARCHAR(255) NOT NULL,
  producer_agent  VARCHAR(32)  NOT NULL,
  status          VARCHAR(16)  NOT NULL DEFAULT 'published'
                  COMMENT 'published/blocked/in_use/archived',
  create_time     DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  KEY idx_type (type),
  KEY idx_producer (producer_agent)
) ENGINE=InnoDB COMMENT='资产主表';

-- 资产版本
CREATE TABLE artifact_version (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  asset_id      VARCHAR(64) NOT NULL,
  version       INT         NOT NULL,
  object_key    VARCHAR(255) NOT NULL COMMENT 'MinIO 对象 key',
  digest        CHAR(64)    NOT NULL COMMENT 'SHA-256 内容摘要',
  status        VARCHAR(16) NOT NULL DEFAULT 'active',
  reviewer      VARCHAR(32) NULL,
  review_status VARCHAR(16) NULL COMMENT 'pending/approved/rejected',
  create_time   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_asset_ver (asset_id, version)
) ENGINE=InnoDB COMMENT='资产版本';

-- 血缘（资产级，跨库语义：任务在 TaskRepo，依赖在 ArtifactRepo）
CREATE TABLE artifact_dependency (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  asset_id      VARCHAR(64) NOT NULL,
  version       INT         NOT NULL,
  dep_asset_id  VARCHAR(64) NOT NULL,
  dep_version   INT         NOT NULL,
  edge_type     VARCHAR(16) NOT NULL DEFAULT 'data_dep',
  KEY idx_asset (asset_id),
  KEY idx_dep (dep_asset_id)
) ENGINE=InnoDB COMMENT='资产血缘';
```

**MinIO 对象 key 约定**：`{type}/{asset_id}/v{version}.{ext}`。数据集/特征集等文本型资产实际为 JSON（`.json` 扩展名），报告为 Markdown。元数据一律在 MySQL，MinIO 只放文件。

## 四、记忆存储（memory_entry，MySQL）

记忆条目统一存 `memory_entry` 表（task_repo 库），检索走 MySQL 关键词匹配（LIKE 评分）：

```json
{
  "agent_id": "sql_agent",
  "source_task": "t88",
  "task_type": "q4_sales_analysis",
  "content": "LEFT JOIN 多对多重复陷阱...",
  "experience_type": "pitfall",
  "tags": ["sql", "join"],
  "created_ts": 1755500000,
  "ttl_ts": 1760600000,
  "access_count": 12
}
```

私有/集体记忆通过 `scope` 字段区分（`private` / `collective`），不做独立向量索引。

## 五、Alembic 约定

```
alembic revision --autogenerate -m "add dag_node"
```

- 迁移脚本唯一事实源；`versions/` 内一个变更一个文件。
- 环境：`alembic upgrade head`（后端 Docker 启动前自动执行，幂等）。
- **禁止**：手写 SQL 建表与迁移并行。

## 六、Redis 键约定

| Key | 结构 | 用途 |
| --- | --- | --- |
| `captcha:{id}` | String + TTL | 验证码一次性校验 |
| `limiter:{scope}` | 令牌桶 | 任务并发限流 |
| `midplat.events` | Pub/Sub | 多副本事件总线桥（EVENT_BUS_REDIS=true 时） |
| `ws:{user_id}` | Hash | WebSocket 在线路由 |
