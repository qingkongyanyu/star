# 消息事件契约（WebSocket / EventHub）

> **实现事实**：平台事件走 `app/bus/event_hub.py` 的 `EventHub`，默认进程内广播；
> 多副本部署时用 Redis Pub/Sub 桥接（`EVENT_BUS_REDIS=true`）。Kafka **不承载平台事件**，
> 仅作为「实时流数据源」被 SQLAgent 消费。

## 一、事件模型

- 生产者：`services/task_service.py`、`services/scheduler.py`、Agent 工具。
- 订阅者：`api/v1/ws.py` 为每个 WebSocket 连接创建一个 `asyncio.Queue`。
- 下行格式：`{ "type": "<event>", "data": {...} }`。
- 进程内：`publish` 直接投递到所有本地队列（队列满时丢弃并 warning）。
- 多副本：开启 `EVENT_BUS_REDIS=true` 后，同时写 Redis 通道 `midplat.events`；
  各进程订阅并回灌本地，按 `instance_id` 去重，避免自己发布的消息重复。

## 二、事件清单

| 事件 | 关键字段 | 产生位置 | 前端用途 |
| --- | --- | --- | --- |
| `task.created` | task_id / requester / node_count / message | 任务创建 | 群聊：天枢收到需求 |
| `planner.ready` | task_id / plan_source / plan_summary / node_count | Planner 拆解完成 | 群聊：展示规划摘要 |
| `node.started` | task_id / node_id / agent_type | 节点开始执行 | 群聊：Agent 登场；看板刷新 |
| `node.failed` | task_id / node_id / agent_type | 节点两次执行均失败 | 群聊/看板：失败提示 |
| `artifact.published` | task_id / node_id / asset_id / version / agent_type / title | 资产发布 | 群聊：产出摘要；资产刷新 |
| `dq.no_data` | task_id / node_id / asset_id / reason | 质检判定无数据 | 任务失败提示 |
| `dq.blocked` | task_id / node_id / asset_id / reason | 质量问题阻断 → 插特征工程 | 看板：阻断高亮 |
| `dq.fe` | task_id / node_id / asset_id / reason | 告警级问题 → 前置清洗 | 看板：FE 节点出现 |
| `review.rejected` | task_id / node_id / asset_id / reason | 终审否决 → 自动修订 | 群聊/看板：修订轮次 |
| `task.completed` | task_id / status / reason? | 任务终态 | 群聊：完成卡片；看板刷新 |

> 事件是**通知**，不是状态真相源：任务/节点/资产的最终状态以 MySQL 查询为准，
> 前端收到事件后重新拉取或按事件信号刷新。

## 三、语义与兜底

1. **非持久化**：进程内队列不保证跨进程/重启的事件回放；崩溃恢复依赖 DB 租约与扫描自愈。
2. **多副本**：Redis Pub/Sub 是广播语义（非持久化）；断线期间的事件不会补发。
3. **丢事件不影响一致性**：调度推进不依赖事件；事件只影响前端即时体验与本地唤醒。
4. **队列背压**：单个 WS 订阅队列上限 1000；满则丢弃并记录 warning，不阻塞调度。
5. **鉴权**：WS 连接建立后首帧发送 `{ "type": "auth", "token": "<JWT>" }`；
   token 不进 URL，避免写入访问日志。

## 四、代码位置

```
app/bus/event_hub.py        # EventHub：publish / subscribe / Redis 桥
app/api/v1/ws.py            # /ws/chat：首帧鉴权 + 事件下行
app/services/task_service.py# task.created / planner.ready
app/services/scheduler.py   # node.* / artifact.published / dq.* / review.* / task.completed
frontend/src/api/ws.ts      # 连接、重连、事件分发
frontend/src/stores/chatStore.ts  # 事件 → Agent 发言
frontend/src/stores/wsEvents.ts   # 事件信号 → 其它页面刷新
```

## 五、与 Kafka 的关系

- `KAFKA_BOOTSTRAP` / `KAFKA_TOPIC` 用于**数据源接入中的 stream 类型**（只读消费 topic）。
- 平台任务事件不写 Kafka；如需审计级事件流，可在 `EventHub.publish` 增加 Kafka 生产者（未内置）。
