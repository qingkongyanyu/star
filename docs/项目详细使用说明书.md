# 星枢 StarPivot · 项目详细使用说明书

> 版本：v3.2 商业版（2026-10-19）｜ 面向本地运维/重启/停止｜ **无内置账号**

---

## 一、系统组成

| 组件 | 技术 | 本地端口 | 用途 |
|---|---|---|---|
| 中间件 | Docker Compose × 4 | 3307 / 6381 / 9092 / 9000 | MySQL / Redis / Kafka / MinIO |
| 业务数据源 | 任意外部数据库/文件/API | 由数据源配置决定 | 被分析的真实数据（独立于平台库） |
| 后端 | uvicorn (FastAPI) | 8070 | REST API + WebSocket |
| 前端 | Vite dev server | 5173 | React UI |

> 宿主机端口刻意避开常见的 3306/6379，避免与本机其它 MySQL/Redis 冲突。

## 二、启动步骤（关机后重新启动用）

### 第 1 步：确认 Docker Desktop 在运行
打开 Docker Desktop，等右下角鲸鱼图标稳定。

### 第 2 步：启动中间件
```bash
cd <项目根>
docker compose up -d mysql redis kafka minio
docker compose ps          # 4 个都 healthy
```

### 第 3 步：确认后端配置
```bash
cp backend/.env.example backend/.env   # 首次
# 编辑 backend/.env：数据库/Redis 地址、LLM Key、BOOTSTRAP_ADMIN_*（首次）
```

首次启动前初始化管理员（二选一）：
```bash
# A. 在 backend/.env 设置 BOOTSTRAP_ADMIN_USERNAME/BOOTSTRAP_ADMIN_PASSWORD
# B. 启动后执行：
cd backend && python -m app.cli create-admin --username admin
```

### 第 4 步：启动后端
```bash
cd backend
../.venv/Scripts/python.exe -m alembic upgrade head   # 首次/升级后
nohup ../.venv/Scripts/python.exe -m uvicorn app.main:app --port 8070 > uvicorn.log 2>&1 &
```
验证：
```bash
curl -s http://localhost:8070/healthz   # 存活
curl -s http://localhost:8070/readyz    # DB/Redis/MinIO 就绪
```

### 第 5 步：启动前端
```bash
cd frontend
npm install      # 首次
nohup npm run dev > npm.log 2>&1 &
```
浏览器打开 **http://localhost:5173**，使用你初始化的管理员账号登录。

## 三、一键启动脚本（推荐）

```bash
cd <项目根>
bash scripts/start_dev.sh
```
脚本会起中间件 → 安装依赖 → Alembic 迁移 → 检查管理员 → 启动后端/前端。
> 若 8070 起不来，按第 4 步手动启动；后端改代码后建议手动重启。

## 四、停止与释放端口

```bash
# 按端口找 PID（避免误杀其它 node/python）
netstat -ano | grep -E ":5173|:8070"
taskkill //F //PID <pid>

# 停止中间件
docker compose down
```

> 平台数据在 Docker volume（MySQL/MinIO）；`docker compose down` 不删数据，
> `docker compose down -v` 会清空，执行前确认。

## 五、功能使用速查

| 功能 | 怎么用 |
|---|---|
| 发分析任务 | 协同群聊（选数据源→输需求→发送）或任务看板（选数据源→下发） |
| 看结果 | 任务工作台 `/task/:id`：数据可视化大屏（图表+表格+报告） |
| 下报告/资产 | 任务工作台或资产仓库 → 预览 / 下载（.md/.sql/.json） |
| 接数据源 | 数据源接入（管理员）→ 新增 MySQL/CSV 等 → 测试连接 |
| 管理指标口径 | 系统管理 → 知识库 → 新增/编辑 → Agent 下个任务生效 |
| 配权限 | 系统管理 → ACL → 例：`analyst + orders + select + 拒绝` |
| 用户管理 | 系统管理 → 用户（新建/改角色/停用） |
| 忘记口令 | `cd backend && python -m app.cli reset-password --username <账号>` |

## 六、常见问题排查

| 症状 | 排查 |
|---|---|
| 前端打不开 5173 | 看 `frontend/npm.log`；结束残留 node 进程后重启 |
| 后端 8070 打不开 | 端口被残留进程占 → `netstat -ano | grep :8070` 杀 PID；看 `backend/uvicorn.log` |
| 启动提示「未检测到启用的管理员」 | 配置 `BOOTSTRAP_ADMIN_*` 或执行 CLI 创建 |
| 登录返回 429 | 触发账号/IP 防爆破阈值；等待锁定时间或调整 `LOGIN_*` 配置 |
| 群聊发消息「没有数据」 | 未选数据源 → 先到「数据源接入」连接 |
| 数据库连不上 | 确认容器 healthy；`docker compose ps`；必要时 `docker compose restart mysql` |
| Kafka 起不来 | 镜像需为 `apache/kafka:3.7.1` |
| 任务全节点 FAILED | 看 `backend/uvicorn.log`；多为数据源不可达或 LLM Key 失效 |
| `/readyz` 显示 degraded | Redis/MinIO 不可用但已降级；检查容器与配置 |

## 七、数据备份提醒

- 平台数据在 Docker MySQL + MinIO（docker volume）；生产请使用云 RDS/对象存储并配置自动备份。
- 本地降级资产在 `backend/data/artifacts/`（仅 MinIO 不可用时的副本，不自动回补）。
- 每次升级前备份 `task_repo`、`artifact_repo` 与 MinIO bucket。
