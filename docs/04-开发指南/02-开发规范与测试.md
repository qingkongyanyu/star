# 开发规范与测试

## 一、Git 工作流

- 分支：`main`（受保护，禁止直接 push）+ `feat/*`、`fix/*`、`docs/*`。
- 提交信息（Conventional Commits）：
  ```
  feat(agents): 实现 SQLAgent 权限校验
  fix(scheduler): 修复认领锁释放竞态
  docs(api): 补充 /admin/audit 分页说明
  ```
- PR 要求：通过 CI（lint + typecheck + pytest）→ 1 人 review → merge。

## 二、后端规范

- 风格：Ruff（`ruff check`）+ Mypy（`mypy app`）。
- 分层依赖：严格遵循 `docs/01-项目结构` 的依赖方向，违反在 review 拦截。
- 类型：所有函数签名带类型标注；Pydantic schema 做 DTO，禁止裸 dict 跨层。
- 异步：I/O 用 `async def`；同步阻塞库（SQLAlchemy 同步）用 `asyncio.to_thread` 包裹。
- 日志：结构化 JSON，含 `request_id`、`actor`、`node_id`；禁 `print`。
- 异常：业务异常抛 `AppError(code, message)`，禁止裸抛 `Exception`。

## 三、前端规范

- 严格 TS（见 03-前端/01）；组件/页面/Hook 命名按目录规范。
- 组件不直接发请求；数据经 store。禁止 `any`（特殊场景注释豁免）。
- 提交前 `npm test && npm run lint && npm run build`。

## 四、测试策略（四层）

| 层级 | 目录 | 覆盖 | 工具 |
| --- | --- | --- | --- |
| 单元 | `backend/tests/unit` | DAG 环检测、ACL 判定、脱敏规则、口径一致性校验、记忆去重阈值 | pytest |
| 集成 | `backend/tests/integration` | DAG 全链路、DQ→FE 分支、复检重试与升级人工、断点续跑、驳回重调度、JWT/角色 | pytest + httpx（TestClient） |
| 评测集 | `backend/tests/eval` | 口径一致性样例、幻觉识别样例、脏数据模式样例（LLM 输出回归） | pytest + 记录评分 |
| 混沌 | 脚本/CI 手动 | MinIO/DB 宕机降级、锁超时、消息重放 | 见 05-DevOps |

```bash
cd backend
pytest                                   # 全量
pytest tests/unit/test_dag_cycle.py      # 单点
pytest -m integration                    # 仅集成
```

### 关键集成用例（评审重点）

1. **DQ→FE 分支**：构造含重复记录的数据集 → 断言发 `dq.blocked` → FE 节点生成 → 清洗 → 复检通过 → 下游强制使用特征集（验证 `output_asset_id` 指向 feature_set）。
2. **复检失败升级**：FE 清洗仍不通过 × 2 → 断言升级人工事件。
3. **断点续跑**：执行到 DQ 节点模拟崩溃 → 重启 → 断言成功节点不重跑，从 DQ 继续。
4. **驳回重调度**：评审驳回 → 断言对应节点新版本资产迭代。
5. **ACL 越权**：只读角色请求 sql_extract 数据源 → 断言 403 + 审计记录。

## 五、测试基建

- `conftest.py`：内存/临时库（MySQL 用 Testcontainers 或 `aiosqlite` mock）、测试 MinIO（本地目录）、MockLLM（确定性输出）、测试 Redis（`fake-redis`）。
- 集成测试默认不真实调用 LLM，用 `MockLLM` 保证确定性；评测集按需连真实模型（CI 配置密钥）。

## 六、代码评审清单

- [ ] 分层依赖方向正确（无 repository→service 反向）
- [ ] 工具已注册且有 schema；Agent 只能调契约内工具
- [ ] SQLAgent 所有 SQL 路径过 ACL + 脱敏
- [ ] 审计钩子覆盖写操作
- [ ] 异常带业务错误码，非 500
- [ ] 前端无 `any`、无直接请求、路由/权限守卫正确
