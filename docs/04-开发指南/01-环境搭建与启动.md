# 环境搭建与启动

> 目标环境：Windows 11 + **Python 3.13.x** + Node 20/22 + Docker Desktop。本文档给出从零到可运行的最短路径。
> 平台为商业版：**没有内置账号**，首次启动必须显式初始化管理员。

## 〇、前置依赖

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| Python | **3.13.x** | 后端运行时（pyproject 约束 >=3.13,<3.14） |
| uv | ≥0.5 | Python 包管理（项目根 `pyproject.toml` / `uv.lock`） |
| Node.js | ≥20（推荐 22） | 前端 |
| npm | 随 Node | 前端包管理（仓库提供 `package-lock.json`） |
| Docker Desktop | 最新 | 起中间件（MySQL/Redis/Kafka/MinIO） |
| Git | — | 代码管理 |

## 一、克隆与配置

```bash
git clone <repo> data-mid-platform && cd data-mid-platform
cp backend/.env.example backend/.env
```

编辑 `backend/.env`：

| 配置 | 说明 |
| --- | --- |
| `DATABASE_URL` / `ARTIFACT_DATABASE_URL` | 本地默认指向 `127.0.0.1:3307` 的 task_repo / artifact_repo |
| `REDIS_URL` | 本地默认 `127.0.0.1:6381` |
| `LLM_BASE_URL` / `LLM_API_KEY` | 可选；不配置时部分 Agent 走确定性兜底 |
| `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` | **首次启动的管理员**；口令 ≥10 位且至少三类字符 |
| `JWT_SECRET` | 本地可保持开发值；生产必须 ≥32 位随机串 |

> 也可以不配置 `BOOTSTRAP_ADMIN_*`，启动后用 CLI 创建：
> `cd backend && python -m app.cli create-admin --username admin`

## 二、起基础设施（中间件）

```bash
docker compose up -d mysql redis kafka minio
docker compose ps          # 全部 healthy 后继续
```

> 首次启动会拉镜像，约几分钟。MinIO 控制台 http://localhost:9001
> （本地开发默认 minioadmin/minioadmin；生产必须替换）。

## 三、后端启动

```bash
# uv 工程文件（pyproject.toml / uv.lock / .venv / .python-version）在项目根
cd <项目根>
uv venv --python 3.13
uv pip install -e ".[dev]"
cd backend
../.venv/Scripts/python.exe -m alembic upgrade head   # 建表（TaskRepo / ArtifactRepo / ACL / 审计）
../.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8070
```

初始化管理员（二选一）：
```bash
# A. 已在 backend/.env 配置 BOOTSTRAP_ADMIN_*：直接启动，首次会自动创建
# B. 用 CLI 显式创建（口令交互输入，或读 BOOTSTRAP_ADMIN_PASSWORD）
python -m app.cli create-admin --username admin
python -m app.cli list-admins
```

验证：
- Swagger（仅非生产）：http://localhost:8070/docs
- 存活探针：http://localhost:8070/healthz → `{"status":"ok",...}`
- 就绪探针：http://localhost:8070/readyz → 数据库/Redis/MinIO 状态

## 四、前端启动

```bash
cd frontend
npm install
npm run dev
```

验证：http://localhost:5173 → 登录页。使用你在上一步初始化的管理员账号登录；
登录页不再展示任何演示账号。

## 五、演示流程（验证全链路）

1. 登录 → 群聊下发：「分析各区域 Q4 销售额，输出报告」。
2. 看板观察 DAG：口径→探查→抽取→质检；若种子数据含脏数据，观察 **DQ 阻断 → 特征工程** 自动分支。
3. 资产仓库看产出血缘；大屏看统计；结束后记忆中心看复盘纪要。
4. 退出登录 → 用只读账号验证无操作按钮（权限体验）。

## 六、常见问题

| 症状 | 处理 |
| --- | --- |
| `alembic` 连接失败 | 确认 MySQL 已 healthy；`backend/.env` 的 `DATABASE_URL` 正确 |
| npm 安装慢 | 换镜像：`npm config set registry https://registry.npmmirror.com` |
| 端口占用 | 改 `.env` / `vite.config.ts` 端口 |
| Kafka 连不上 | 确认 `KAFKA_BOOTSTRAP=127.0.0.1:9092` 且容器 healthy |
| LLM 调用失败 | 检查 `LLM_BASE_URL/API_KEY`；本地可先用 Mock（`infra/llm.py` 提供 `MockLLM`） |
| 启动报「未检测到启用的管理员」 | 配置 `BOOTSTRAP_ADMIN_*` 或执行 `python -m app.cli create-admin` |
| 登录返回 429 | 触发了账号/IP 防爆破阈值；等待 `LOGIN_LOCKOUT_SECONDS` 或调整配置 |
| 忘记管理员口令 | `cd backend && python -m app.cli reset-password --username <账号>` |

## 七、一键脚本

`scripts/start_dev.sh`：起中间件 → 安装依赖 → 迁移 → 检查管理员 → 启动后端（后台）→ 启动前端 → 打印访问地址。仅用于本地开发。
